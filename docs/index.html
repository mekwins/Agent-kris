🧠 Brain

A personal AI second brain — compile, search, and grow your knowledge through Claude Desktop.

✓ MCP Server (SSE) ✓ Compile agent ✓ API key auth ✓ Hybrid search ◷ Live connectors (planned)

What is this

Brain is a local, AI-powered knowledge management system built around a markdown vault. Two active layers:

  • MCP Server — 6 tools Claude Desktop calls to search, write, recall, and compile vault content. Runs as a persistent SSE HTTP service on localhost:8765, protected by an API key.
  • Compile Agent — an Anthropic API agentic loop (Claude Sonnet via Azure AI Foundry) that reads inbox/, extracts knowledge, writes interlinked wiki pages, and moves processed files to processed/.

Your primary interface is Claude Desktop. You talk to Claude; Claude calls brain tools on your behalf. No terminal required for day-to-day use.

Core pattern
You write rough notes → brain_write saves to inbox → brain_compile runs the agent → structured wiki pages appear with wikilinks, inbox file moves to processed/ → brain_search finds everything later.

Remote-ready design
The SSE + API key setup means you can move the server to any host (VPS, Coolify) by changing one URL in the Claude Desktop config. The mcp-remote bridge handles the rest — same as the Nextrace connector pattern.

Installation

  1. Install Python dependencies 
    cd /Users/krzysztofmekwinski/Desktop/Agent-kris
uv sync
  2. Create .env — see Environment variables below
  3. Bootstrap the vector index (first time, or after bulk vault changes) 
    uv run python scripts/index_vault.py
  4. Register the LaunchAgent — starts the server automatically on login 
    launchctl load ~/Library/LaunchAgents/com.kris.brain-mcp.plist
  5. Add brain to Claude Desktop config — see Connect to Claude Desktop
  6. Restart Claude Desktop — Cmd+Q then reopen

Environment variables

File: .env in the project root. All fields required except MCP_API_KEY (but strongly recommended).

# Azure OpenAI — embeddings (text-embedding-3-small)
EMBEDDING_ENDPOINT=https://<resource>.openai.azure.com/openai/deployments/text-embedding-3-small/embeddings?api-version=2023-05-15
EMBEDDING_API_KEY=<azure-openai-key>

# Azure AI Foundry — compile agent (Claude Sonnet)
ANTHROPIC_FOUNDRY_BASE_URL=https://<resource>.cognitiveservices.azure.com/anthropic/
ANTHROPIC_FOUNDRY_API_KEY=<foundry-key>

# Vault paths
VAULT_PATH=./vault
VECTORS_PATH=./vault/.vectors.json

# MCP server API key — required for all SSE connections
MCP_API_KEY=<strong-random-key>
Keep .env out of git
.env is gitignored. Never commit it. Use .env.example to document shape without real values. Generate MCP_API_KEY with: python3 -c "import secrets; print(secrets.token_urlsafe(32))"

Connect to Claude Desktop

The brain server runs as a persistent SSE service. Claude Desktop connects through mcp-remote, which bridges stdio (what Claude Desktop speaks) to HTTP SSE (what the server speaks) — same pattern as the Nextrace connector.

Edit ~/Library/Application Support/Claude/claude_desktop_config.json:

{
  "mcpServers": {
    "brain": {
      "command": "/path/to/run-npx.sh",
      "args": [
        "mcp-remote",
        "http://127.0.0.1:8765/sse",
        "--header",
        "x-api-key:<your-MCP_API_KEY>"
      ]
    }
  }
}
Moving to remote hosting
When you host the server on a VPS or Coolify, change only the URL: http://127.0.0.1:8765/sse → https://brain.yourdomain.com/sse. The API key header stays the same.

MCP Tools

Ask Claude in natural language — it picks the right tool. You never call tools directly.

brain_write
Capture anything to inbox/ and auto-embed for search. Starting point for every piece of content.
content tags domain: work | personal | learning title source_url
brain_compile
Run the compilation agent. Processes inbox → wiki pages, moves compiled files to processed/, updates index and log.
task: compile inbox | compile sources | lint | search limit: int query: string (search task only)
brain_search
Search wiki and source content. Hybrid mode combines semantic vector search with keyword matching.
query scope: all | work | personal | learning mode: hybrid | semantic | keyword limit: int
brain_recall
Fetch a specific wiki page and its wikilinked neighbors. Best for deep-diving a concept.
topic depth: 1 | 2
brain_context
Returns the 10 most recently updated pages for a persona. Use at the start of a session to prime Claude with relevant context.
agent_type: work | personal | research
brain_relate
Find the connection between two concepts — shared tags and shortest wikilink path between them.
concept_a concept_b

Compile agent

Triggered via brain_compile. Runs as an Anthropic API agentic loop with its own filesystem tools — fully autonomous once triggered.

What happens on "compile inbox"

  1. Lists inbox/ files with status: inbox
  2. Reads each file and classifies domain + content type
  3. Searches existing wiki for related pages (to generate wikilinks)
  4. Writes structured wiki page to the correct folder (concepts/, people/, projects/, areas/, or brainstorm/)
  5. Embeds the new page into the vector store for semantic search
  6. Moves the inbox file to processed/ — inbox stays clean
  7. Updates wiki/index.md TOC and appends to wiki/log.md

Tasks supported

TaskWhat it does
compile inboxProcess all unread inbox files → wiki pages, move to processed/
compile inbox limit=5Same, max 5 files per run
compile sourcesRecompile from sources/ after connector sync
lintReport broken wikilinks, orphan pages, bad frontmatter

Wikilinks

Pages link to each other with [[Page Title]] syntax. The compile agent searches for existing pages before writing, so links are woven in automatically.

  • Link targets must match the title frontmatter of an existing wiki page
  • Broken links are reported by the lint task
  • brain_recall follows wikilinks to depth 1 or 2
  • brain_relate finds shortest paths between two concepts

Managing the server

The MCP server runs as a macOS LaunchAgent — starts on login, restarts automatically if it crashes.

ActionCommand
Check server is upcurl -o /dev/null -w "%{http_code}" http://127.0.0.1:8765/sse --max-time 2 → expect 200
Restart after code changeslaunchctl stop com.kris.brain-mcp && launchctl start com.kris.brain-mcp
View live logstail -f ~/Library/Logs/brain-mcp.log
Stop completelylaunchctl unload ~/Library/LaunchAgents/com.kris.brain-mcp.plist
Re-enable on loginlaunchctl load ~/Library/LaunchAgents/com.kris.brain-mcp.plist
Restart required after code changes
Any edit to src/ files requires a server restart — Python loads modules at startup and the running process has the old code in memory.

Troubleshooting

Brain tools not showing in Claude Desktop

  • Verify server is running: curl -o /dev/null -w "%{http_code}" http://127.0.0.1:8765/sse --max-time 2 → must return 200
  • If server is down: launchctl start com.kris.brain-mcp then check ~/Library/Logs/brain-mcp.log
  • Verify the x-api-key value in Claude Desktop config matches MCP_API_KEY in .env
  • Restart Claude Desktop after any config change (Cmd+Q, not just close)
  • Check Claude Desktop MCP logs: tail ~/Library/Logs/Claude/mcp.log

Missing env var error on startup

Check .env has all five keys: EMBEDDING_ENDPOINT, EMBEDDING_API_KEY, ANTHROPIC_FOUNDRY_BASE_URL, ANTHROPIC_FOUNDRY_API_KEY, MCP_API_KEY.

Search returns no results

Vector index may be empty or stale. Run uv run python scripts/index_vault.py to rebuild. Keyword search works without the index.

Compile agent fails or stalls

  • Check Azure AI Foundry quota and endpoint availability
  • The agent has a 50-iteration safety cap — for large batches use limit=5 to process in chunks
  • Test connectivity: uv run python -c "import asyncio; from src.agent import run; print(asyncio.run(run('lint')))"

Inbox files not moving to processed/

The server must be restarted after the _mark_processed change. Run: launchctl stop com.kris.brain-mcp && launchctl start com.kris.brain-mcp
